# 20260624_给你阅读_跨层统一实体重构方案

## 1. 这次重构在解决什么问题

当前图库已经把 `base`、`retrieval`、`discovery` 三层都写进了 Neo4j，但存在一个结构性问题：

- 同一个语义实体在 `base` 里已经有正式节点
- 到了 `retrieval` 或 `discovery`，又被复制成新的层内节点
- 结果图里出现的是多份“语义相同、身份不同”的副本

这和项目“以本体为核心”的目标不一致。

你要的其实不是：

- 给 `retrieval` 或 `discovery` 节点再补几个类型标记

你真正要的是：

- 同一个事实、争点、证据、法条要素，在三层里尽量共用同一个实体身份
- `retrieval` 和 `discovery` 只表达“它们如何使用这些实体”，而不是再复制一套

## 2. 重构后的核心原则

这次重构建议遵守 3 条原则：

### 2.1 统一实体

- `base` 中已经存在的正式实体，只保留一份
- `retrieval` 和 `discovery` 优先直接引用这份实体
- 不再把同一个实体默认复制成新的层内节点

### 2.2 层级通过关系表达

- 某个实体被哪一层使用，不再主要靠复制节点表达
- 而是通过“某条检索记录引用了它”“某条发现记录使用了它”这类关系表达

### 2.3 派生对象继续保留

并不是所有层内对象都要消失。

下面这些仍然应该保留：

- 检索条目
- 发现记录
- 真正只属于某一层的派生节点
- 无法对齐到正式实体时的兜底锚点

也就是说，重构不是“把派生层删掉”，而是“把可复用的实体收回到统一本体里”。

## 3. 业务上会怎么变化

如果按这套方案落地，图库的语义会变成：

- `base` 负责提供正式实体和正式关系
- `retrieval` 负责说明某条检索资产引用了哪些正式实体
- `discovery` 负责说明某条发现记录引用了哪些正式实体、又提出了哪些新推断

这样一来：

- 查一个争点时，不会再看到 base 一份、retrieval 一份、discovery 一份的平行副本
- 查某条检索结果时，可以直接看到它引用了哪些正式实体
- 查某条发现记录时，也能直接看到它是基于哪些正式实体得出的

## 4. 这次重构最重要的收益

### 4.1 图谱会更像“统一知识图谱”

如果不重构，后面 retrieval 和 discovery 会持续复制更多实体，图库会越来越像“分层快照堆叠”。

重构后会更接近你期望的形态：

- 本体实体只有一份
- 各层围绕这份实体产生引用、补充和推理

### 4.2 跨层查询会更自然

后续无论你从 `base`、`retrieval` 还是 `discovery` 角度看同一个实体，都更容易落到同一个节点上。

这对下面几件事都更有利：

- 节点详情聚合
- 跨层追溯
- 图一致性核查
- 后续图推理和对比分析

### 4.3 后续更新会更稳

当同一文书反复更新时，如果三层都在复制实体，更新和对齐会越来越难。

统一实体后：

- 上游更新更容易判断哪些是同一个实体
- 下游也更容易保持对这些实体的稳定引用

## 5. 这次重构不会改变的部分

这次不是推翻整个现有架构。

以下方向仍然保留：

- `base` 仍然是正式解析事实层
- `retrieval` 仍然是检索资产层
- `discovery` 仍然是发现层
- 分层写入、分层核查、分层更新仍然成立

变化点主要在于：

- “层”不再靠复制实体来表达
- “层”更多通过记录节点、引用关系和版本关系来表达

## 6. 对你阅读和确认最关键的判断点

这次你需要确认的不是代码细节，而是下面几个业务判断：

### 6.1 是否接受“本体实体只保留一份”

建议答案：接受，而且这应该成为后续默认原则。

### 6.2 是否接受“retrieval / discovery 优先引用，不再默认复制”

建议答案：接受。

因为如果不这样做，后面图库会越来越偏离“本体为核心”的路线。

### 6.3 是否接受“只把真正新增的层内对象保留为派生节点”

建议答案：接受。

因为这样既不会丢掉层内语义，又不会把已有实体重复造一遍。

## 7. 建议的推进顺序

为了稳妥落地，建议按下面顺序推进：

1. 先改 `retrieval`
2. 再改 `discovery`
3. 再统一统计口径、差异对比口径和子图查询口径
4. 最后再清理旧的副本节点路径

原因很简单：

- `retrieval` 规则更清晰，更适合作为第一阶段试点
- `discovery` 里存在更多新增推理节点和兜底锚点，适合第二阶段收口

## 8. 对用户体验的直接影响

如果按这套方案完成，用户可感知的变化主要有：

- 图里的“重复语义节点”会减少
- `retrieval` 和 `discovery` 的写入结果会更容易解释
- Database 里层间 diff 会更符合真实业务语义
- 查询一个实体时，更容易同时看到它在不同层中的使用情况

## 9. 本文结论

这次重构的本质不是“给现有层内节点补类型”。

而是：

- 把正式实体收回到一套统一本体里
- 让 `retrieval` 和 `discovery` 改为引用这些实体
- 只把真正新增、无法复用的对象留在派生层

这条路线更符合你前面反复强调的目标：

- 主图
- 本体
- Neo4j

三者最终应尽量统一，而不是长期各说各话。
