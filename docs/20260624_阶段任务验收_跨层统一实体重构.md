# 20260624_阶段任务验收_跨层统一实体重构

## 1. 文档目的

本文只负责一件事：

- 把“跨层统一实体重构”拆成分阶段任务，并明确每个阶段你需要确认什么、怎么联调、怎么验收

本文不展开具体代码实现细节，避免和技术细化文档混在一起。

## 2. 总体验收目标

最终验收标准不是“多写了多少节点”，而是下面 4 件事是否成立：

1. 同一个语义实体在 `base`、`retrieval`、`discovery` 中尽量对应同一个正式节点
2. `retrieval` 和 `discovery` 能表达自己的层语义，但不再默认复制正式实体
3. Database 的 diff、状态和子图解释能和新的图语义一致
4. 分层更新后，不会把现有层关系和统计口径搞乱

## 3. 阶段划分

建议分 4 个阶段推进。

### 阶段 1：retrieval 实体引用优先

#### 阶段目标

- 先在 `retrieval` 层实现“能复用 base 实体就不复制”
- 把最典型的重复节点来源先收口

#### 本阶段完成后，你应看到的结果

- 一条 retrieval 写入成功后
- 不再默认生成一批与 base 平行的实体副本
- 对于能对齐的节点，会体现为 retrieval 对 base 实体的引用

#### 联调重点

- 选 1 个已有 base 写入完成的文书
- 执行 retrieval 写入
- 检查争点、事实、证据等典型实体是否仍然只有一份正式节点
- 检查 retrieval 是否还能完整表达自己的链路语义

#### 验收方式

- 你在图里查看同一类典型实体时，不再看到明显的 retrieval 平行副本泛滥
- retrieval 写入结果能解释为：
  - 写入了多少条检索记录
  - 引用了多少个正式实体
  - 新增了多少个兜底派生节点

#### 本阶段通过标准

- retrieval 基本链路可写
- 可对齐实体优先复用 base
- 现有功能没有因为这一步直接失效

### 阶段 2：discovery 实体引用优先

#### 阶段目标

- 将 discovery 中本可复用的实体也收回到统一本体
- 把真正新增的推理节点和兜底文本锚点区分开

#### 本阶段完成后，你应看到的结果

- discovery 不再默认把所有端点都写成新的层内节点
- 能对齐到正式实体的，会直接引用正式实体
- 只有真正新增概念或无法对齐时，才保留派生节点或文本锚点

#### 联调重点

- 选 1 个 discovery 结果较丰富的文书
- 检查 discovery 中引用 base 实体的比例是否明显提高
- 检查真正新增推理节点是否仍可保留
- 检查无法对齐的端点是否被合理降级为文本锚点

#### 验收方式

- 你查看 discovery 结果时，能清楚区分：
  - 正式实体引用
  - 新增推理节点
  - 兜底文本锚点

#### 本阶段通过标准

- discovery 不丢语义
- 同时又明显减少“看起来像正式实体、实际上是 discovery 副本”的情况

### 阶段 3：Database 口径切换

#### 阶段目标

- 让 `diff`、`status`、`subgraph` 的解释口径跟上新模型
- 避免前端还在按“副本节点数量”解释差异

#### 本阶段完成后，你应看到的结果

- retrieval 和 discovery 的统计信息不再只围绕旧副本节点数量
- 页面上能区分：
  - 记录数
  - 引用实体数
  - 派生节点数
  - 文本锚点数

#### 联调重点

- 对同一文书分别查看 base、retrieval、discovery 的 Database 状态
- 核对统计文案是否能和实际图库结构对应
- 检查 subgraph 是否还能正确展示当前层的有效内容

#### 验收方式

- 你能看懂每一层到底“写了什么”
- 不会再出现“明明没多出新实体，却因为复制节点太多导致统计失真”的体验

#### 本阶段通过标准

- Database 页面对新图模型的解释成立
- diff 和状态展示能支持继续联调，而不是拖后腿

### 阶段 4：旧副本模型清理

#### 阶段目标

- 在新模型稳定后，逐步清理旧主路径
- 让旧副本标签彻底退居兜底或退出主流程

#### 本阶段完成后，你应看到的结果

- `RetrievalGraphNode` 不再是默认主路径
- `DiscoveryNode` 不再是默认主路径
- `DiscoveryAnchor` 只保留兜底语义

#### 联调重点

- 检查新写入文书是否基本都走新路径
- 检查旧数据是否仍能被查询与解释
- 检查前端是否没有残留对旧副本标签的强依赖

#### 验收方式

- 新文书主要使用“统一实体 + 引用关系”的模式
- 旧副本模型即便还在，也不再主导日常结果解释

#### 本阶段通过标准

- 主路径完成切换
- 旧模型风险可控

## 4. 每阶段都要核对的共性事项

无论在哪个阶段，每次联调都建议固定核对下面 6 项：

1. 同一文书下是否出现明显重复的正式实体
2. retrieval / discovery 是否还能完整表达自己的层语义
3. 写入结果是否能被页面正确解释
4. Database 状态是否和图里实际结构一致
5. 同一典型实体能否在多层结果中被统一识别
6. 本轮改动是否影响已有 base 一致性

## 5. 推荐的联调样本

建议固定选 2 类样本：

### 样本 A：结构相对清晰的文书

用途：

- 优先验证“统一实体”是否生效
- 便于人工观察同一争点、事实、证据是否只保留一份

### 样本 B：retrieval / discovery 较丰富的文书

用途：

- 验证派生层是否仍能保留足够语义
- 验证新增推理节点、文本锚点与正式实体引用的边界

## 6. 你每阶段最值得确认的问题

为了减少你看技术细节的负担，每阶段你重点只需要回答下面的问题。

### 阶段 1 你确认什么

- retrieval 是否开始优先引用正式实体，而不是继续默认复制

### 阶段 2 你确认什么

- discovery 是否也开始优先引用正式实体，并且保留了真正需要的新增节点

### 阶段 3 你确认什么

- Database 页面对新模型的解释是否终于说得通

### 阶段 4 你确认什么

- 旧副本模型是否已经不再主导系统主路径
