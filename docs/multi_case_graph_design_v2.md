# 数据库多案知识图谱：分层对齐与星系聚类可视化设计 (V2)

## 1. 痛点分析：为什么之前的方案和现状很乱？
当前主图（无论单案还是多案）的核心问题在于**物理引擎失控**与**节点无主次**：
1. Vis.js 默认的力导向（Force-Directed）算法会将所有有连线的节点往中心拉扯，形成“毛线球”。
2. 法条、事实、人物、证据混杂在同一个物理平面上，没有视觉层级。
3. 当复数案件同时存在并共享某个法条时，不同案件的专属节点（如事实、证据）会因为引力相互穿插，导致完全无法阅读。

## 2. 核心视觉理念：“星系联邦” (Galactic Federation) 布局
为了强化复数案件的“共性”与“差异”，我们必须对图谱进行**空间强制分层**，并引入**隐形骨架**技术。

整个图谱在垂直空间上分为明确的三层：

### 🔝 T0 级：共性天体层 (Global Anchors)
* **内容**：所有选中案件**共享**的标准化节点（如：相同的 `LegalProvision` 法条、相同的 `CaseType` 案由）。
* **布局干预**：计算图谱的顶部中心区域，将这些共享节点的 `Y 坐标` 强制固定 (`fixed: { y: true }`)。
* **视觉强化**：尺寸放大 1.5 倍，外加明显的光晕 (shadow)。它们是连接不同案件的“桥梁”。

### 🌍 T1 级：案件行星层 (Case Hubs)
* **内容**：每个案件的核心锚点（即 `CourtCase` 节点）。
* **布局干预**：在 T0 层下方，分配一个固定的 `Y 坐标` 水平带。如果是 3 个案件，就在这条水平带上等距排列 3 个 `CourtCase` 节点。通过给它们赋予不同的 `X 坐标` 预设值，强制将它们水平拉开。
* **视觉强化**：为每个案件分配一个主题色，案件节点及其连线均使用该主题色。

### 🌑 T2 级：专属卫星层 (Case Specifics)
* **内容**：各案件独有的 `Fact`（事实）、`Evidence`（证据）、`JudgmentResult`（裁判结果）。
* **布局干预**：不做坐标锁定，完全交由物理引擎处理。由于它们的父节点（T1 层）已经被横向拉开，这些子节点会自然悬垂在各自所属案件的下方，形成互不交叉的“独立星系”。

## 3. 降噪与折叠管道 (Noise-Reduction Pipeline)
在将数据喂给 Vis.js 之前，必须通过一个纯函数管道进行清洗，解决节点爆炸问题：

1. **同类智能聚合 (Smart Aggregation)**：
   * 当某个案件下的 `Evidence` 或 `Fact` 数量超过 3 个时，管道自动将其合并为一个 `[证据组: N项]` 聚合节点。
   * 聚合节点采用中性灰色块 (`shape: box`) 呈现，极大减少视觉面积。
2. **关系重定向 (Edge Rerouting)**：
   * 节点被折叠后，原先指向这些具体证据的边，由管道算法自动改写，指向聚合节点，确保图谱逻辑链不断裂。
3. **低优过滤 (Low-Priority Culling)**：
   * 默认隐藏 `Judge`、`Attorney`、`Person` 等对跨案分析意义不大的边缘节点，可通过右上角控制器重新开启。

## 4. 深度交互：聚光灯与暗化 (Spotlight & Dimming)
复数案件的图谱必须依赖强交互才能进行对比分析：

* **共性溯源 (Hover T0)**：当鼠标悬停在顶部的某个共享“法条”上时，该法条及连接到它的所有 `CourtCase` 节点保持高亮，其余无关联的案件及其事实分支透明度降至 20%（Dimming）。一眼看清“这个法条用在了哪几个案子里”。
* **差异隔离 (Hover T1)**：当鼠标悬停在某个 `CourtCase` 上时，高亮该案件的完整子树（事实、证据链），同时虚化其他案件。

## 5. 核心代码落地指南 (Actionable Steps)

### Step 1: 多案数据融合机制 (`selectors.js`)
开发 `buildMultiCaseGraph(caseKeys, state)`：
* **去重策略**：标准化实体（如法条）的 `id` 直接使用 `hash(内容)`。当合并多案数据时，相同的法条自然融合为一个节点。
* **隔离策略**：非标准化实体（如证据）的 `id` 强制加上 `${caseKey}_` 前缀，确保各案事实物理隔离。

### Step 2: 布局引擎极限调优 (`DatabaseGraph.js`)
放弃自由度过高的力导向算法，改用带极强防重叠机制的配置：
```javascript
physics: {
  solver: 'barnesHut',
  barnesHut: {
    gravitationalConstant: -4000, // 极强的斥力，把案件子节点推开
    centralGravity: 0.05,         // 削弱向心力，防止缩成一团
    springLength: 150,            // 较长的弹簧，给予文字标签足够的展示空间
    avoidOverlap: 1               // 强制防重叠，终结“毛线球”
  }
}
```

### Step 3: 坐标干预算法 (Pre-Positioning)
在调用 `vis.DataSet.add()` 之前：
```javascript
nodes.forEach(node => {
  if (node.type === 'LegalProvision' && node.isShared) {
    node.y = -300; // 钉在顶部
    node.fixed = { y: true };
  } else if (node.type === 'CourtCase') {
    node.y = 0;    // 钉在赤道
    node.fixed = { y: true };
    node.x = calculateXSpacing(node.caseIndex, totalCases); // 水平拉开
  }
});
```

本方案通过**数据层合并去重 + 管道层折叠降噪 + 渲染层坐标强制干预**，彻底解决了多案展示乱成一团的顽疾，不仅易于编码落地，且具备极强的视觉冲击力。
