# 工作台与图谱系统开发进度备忘录

> 记录当前轮次的核心开发进展、架构变更及遗留待办事项。

## 一、 已完成的核心工作 (What We Did)

在本轮对话中，我们主要围绕 **“数据增强(Data Augmentation)”** 与 **“深度思考/知识发现(Deep Thinking & Knowledge Discovery)”** 展开了从底层本体论到前端 UI 的全链路重构：

### 1. 深度思考 (Deep Thinking) 全链路闭环
- **接口与流式传输**：在后端 `app.py` 中新增了 `/api/deep-think` 接口，打通了大模型的 SSE 流式输出（Server-Sent Events）。
- **混合输出解析**：设计了“先输出 Markdown 思考过程，后输出 JSON 增量图谱数据”的 Prompt 策略，并在前端实现了流式打字机渲染与正则表达式的精准截取。
- **UI 交互重构**：重构了右侧 TerminalPanel 的知识发现面板。实现了：
  - **历史记录机制**：每次分析生成一个横向 Tab（如“证据采信 (14:35)”），支持多记录随时回看。
  - **JSON 可视化**：引入 `renderjson` 库，实现了与左侧解析数据对齐的层级可折叠 JSON 树展示。
  - **局部子图联动**：分析完成后，自动将新增的节点和边渲染至右侧独立的“子图”Tab 中，并提供“合并至主图谱”的功能按钮。

### 2. 本体论 (Ontology v2.3) 底层手术级升级
为了让大模型的深度推理能够真正转化为结构化知识，我们对 `legal_ontology_v2.yaml` 进行了基石级别的扩充：
- **新增高阶实体**：
  - `SentencingCircumstance` (量刑情节/酌定情节)
  - `EvidenceChain` (证据链)
  - `LegalInterpretation` (法条特定解释)
- **新增高阶关系 (横向网络)**：
  - 引入了 `corroborates` (相互印证) 和 `contradicts` (相互矛盾) 用于构建证据对抗网络。
  - 引入了 `mitigates` (减轻处罚) / `aggravates` (从重处罚) 用于打通量刑情节与最终判决的逻辑链路。
- **解析引擎适配**：同步修改了后端的 `parser.py` 与提示词快照引擎，确保大模型生成的上述新实体能被正确提取和分配 UI 样式（如黄色椭圆、圆柱体等）。

### 3. 数据增强与法条补充
- **Milvus 向量检索集成**：在后端接入了针对 `legal_provisions_v1` 库的 HTTP API 查询，修复了阿拉伯数字（如“153”）到中文大写条文（如“第一百五十三条”）的正则转换匹配问题。
- **内容回填**：实现了点击“法条补充”后，将向量库中查到的完整法条原文补充进解析数据中，并生成新的快照版本。

## 三、 尚未完成与待解决的事项 (What's Left To Do)

虽然主干流程已通，但要达到完美的业务级应用，以下重点事项仍需在后续推进：

### 1. 深度思考 Prompt 的精细化调优 (重点)
- **现状**：目前大模型虽然能输出符合 v2.3 规范的 JSON，但后端的 `app.py` 中使用的往往是一个相对通用（或硬编码）的 Few-shot 示例。
- **待办**：需要针对矩阵中的 5 种思考类型（法条适用分析、构成要件分析、证据采信分析、裁判尺度分析、诉求抗辩分析），**分别定制专属的 System Prompt 和 Few-shot 示例**。例如：告诉模型在做“证据分析”时必须且只能使用 `corroborates` 边，在做“裁判尺度”时必须输出 `SentencingCircumstance` 节点。

### 2. “合并至主图谱”功能的深层鲁棒性测试
- **现状**：前端已经提供了合并按钮，能够将 `new_nodes` 注入到 `virtual_nodes` 并重绘画布。
- **待办**：当用户在单次会话中进行多次、不同类型的深度思考，并多次点击“合并”时，需要确保图谱 ID 不会冲突、边能够正确挂载到原有的事实/证据节点上，并且撤销/版本回退功能不会崩溃。

### 3. 多智能体架构 (Multi-Agent) 的融合对接
- **现状**：根据 `docs/` 下的记忆文档，项目正在规划基于 LangGraph 的 Supervisor-Worker 多智能体架构（Researcher, Analyzer, Drafter）。
- **待办**：当前的“深度思考”是前端直接调用后端的单次 LLM 推理。未来需要考虑是否将这些分析能力交由后端的专职 Agent（如 Analyzer）来执行，以支持更复杂的、带工具调用的多轮推理。

### 4. Database 页面（案例库浏览器）的同步升级
- **现状**：底层本体论（Ontology）新增了证据链、量刑情节等元素，但 `index.database.html` 相关的检索引擎或可视化逻辑尚未适配这些新特性。
- **待办**：后续若要实现“基于量刑情节的精准类案检索”，需同步改造数据库浏览页的过滤条件和视图层。
