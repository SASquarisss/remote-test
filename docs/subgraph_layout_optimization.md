# 知识发现与子图展示的交互布局优化方案

## 一、 当前问题理解与现状分析

根据你的反馈，我们目前在工作台的 UI 布局与功能上存在以下几个体验上的冲突点：

1.  **历史状态遗留问题**：目前的“链式思考”虽然在后台是按顺序执行的，但如果没有在执行前清除上一次的历史记录，会导致右侧知识发现 Tab 下堆积大量重复或过期的过程 Tab。
2.  **子图样式割裂（盲区）**：你指出证据节点的形状在浮窗上的子图依然是“椭圆”，这说明在前端代码中，除了我刚才修改过的“深度思考子图（`renderDiscoverySubGraph`）”外，还有一处渲染逻辑（`renderSubGraph`）没有应用到最新的 `defaultStyles` 字典。
3.  **两个子图 Tab 的定位混淆**：
    *   **终端中间“知识发现”Tab 下的局部子图**：对应的是 `renderDiscoverySubGraph`，展示的是大模型通过“深度思考”**刚刚脑补/推演出来的虚拟节点和边**（比如新增的量刑情节、法条要件等），供你决定是否要“合并至主图谱”。
    *   **终端右侧独立的“子图 (SubGraph)”Tab**：对应的是 `renderSubGraph`，它展示的是你在最左侧面板点击**“检索资产 (Retrieval Asset)”**时，系统为你提取出来的**单条链路快照**（例如“事实->证据->焦点”的单线逻辑链）。
4.  **宏观与微观视野的冲突**：在进行链式推理时，你希望既能看到每一步推演产生的新子图（微观视角），又能同时审视这些新节点融入主图谱后的整体变化（宏观视角）。但目前的布局需要你频繁切换 Tab，体验非常割裂。

## 二、 页面布局复用与拓展方案设计

针对你的第 4 点需求（既看每个环节的子图，又看全景主图），我设计了以下空间布局拓展方案，**旨在最大化复用现有组件，而不破坏当前的 Flex 弹性结构**：

### 核心思路：左中右三栏联动 + 悬浮画中画 (Picture-in-Picture)

目前的终端分为三大块（从左到右）：
- `Left (termControls)`：检索资产/解析历史
- `Middle (termJsonColumn)`：JSON数据/知识发现
- `Right (termWorkspace)`：主图谱/深度思考/右侧子图

为了实现“边看推演子图，边看主图全貌”的需求，我们可以打破“互斥显示”的限制，采用**画中画（或悬停面板）**的设计：

#### 方案细节

1.  **主舞台归还给主图谱 (`ParseGraph`)**：
    在执行链式思考期间，**强制将最右侧的 `termWorkspace` 切换到“图谱应用 (主图谱)”视图**。这样，随着每一步推演结果的返回和合并，你可以实时看到主图谱上节点像细胞分裂一样长出新的分支。

2.  **将深度思考子图改造为“悬浮控制台 (Floating Panel)”**：
    *   取消终端中间知识发现面板右半部分那个僵硬的子图区域。
    *   当大模型返回某一步（例如：证据采信分析）的 JSON 结果时，将这些新增节点渲染在一个半透明的、可拖拽的**浮动悬窗 (Draggable Overlay)** 中，悬停在主图谱的右下角或左上角。
    *   **交互逻辑**：你在浮窗（微观）里确认这几个证据节点和连线没问题，点击浮窗里的“确认合并”按钮。伴随着动画，这些节点会“飞”入底层的主图谱中，与全案数据（宏观）融为一体。

3.  **重新定义右侧“子图 (SubGraph)”Tab**：
    *   将右侧的“子图” Tab 明确更名为 **“检索链路 (Retrieval Chain)”**，彻底与深度思考功能剥离。
    *   它专门且只用于服务左侧栏的“检索资产”点击事件，作为数据导出前的内容核对面板。

4.  **知识发现 Tab 的纯文本化**：
    *   既然子图被提拔成了悬浮窗，终端中间的“知识发现”面板就可以完全释放空间，专注于展示大模型的 **“思考过程 (Reasoning)”** 和 **“JSON 数据树”**。
    *   在链式思考时，中间面板会像控制台日志一样，从上到下滚动打印：`[证据分析完毕] -> [诉求抗辩完毕] -> ...`，体验更加沉浸。
