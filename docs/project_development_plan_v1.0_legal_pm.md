## 四、法条提取率 30% → 80%+ 系统性解方案

### 4.1 瓶颈根因分析

从 20 条样本深度分析可知：

```
无法条提取的 14 条中：
├── 5 条是非诉讼案件（调解/司法救助）→ 正常，无需法条
├── 3 条是诉讼但文本无显式法条引用 → 需要案由映射兜底
├── 5 条是 LLM 漏提取（文本中有法条但 LLM 忽略）→ 需要正则补充 + prompt 优化
└── 1 条是长文本截断导致提取失败 → 需要压缩/分段策略
```

### 4.2 三层增强管道（已实施 + 优化）

```
Layer 1: LLM 提取（≈50% 覆盖率）
  问题：长文本漏提取、法条格式识别不稳定
  优化：
  ├── text_compressor 关键字段强制保留
  ├── judgment_reason > 2000字 → 分段输入
  └── prompt 增加「法条统计要求」：必须输出提取到的法条数量

Layer 2: 正则补充（≈5% 增量）
  问题：只捕获显式引用，对简写/隐式引用无效
  优化：
  └── 已在 v2.2 修复 typo + 支持同法多条 + 扩展后缀

Layer 3: 案由映射兜底（≈25% 增量）
  当前映射表仅 15 种案由，覆盖不足
  优化：
  ├── 扩展至 100+ 案由（按刑事/民事/行政频次排序）
  ├── 映射添加 applicable_score：0.99（明确对应）~ 0.70（推断适用）
  └── use_mapping 默认启用
```

### 4.3 预计提升路径

```
当前：30%（LLM 提取 30% + 正则 5% + 案由映射目前未默认启用）
Phase 1：80%（启用映射 + 扩展 100 案由 + prompt 优化）
Phase 2：90%（多模型 + 增加 200+ 案由映射 + 隐式引用推断）
Phase 3：92%+（正式法条库校验 + 10,000 条规模验证）
```

### 4.4 法条映射表扩展策略

| 案由类型 | 现有数 | Phase 1 目标 | 策略 |
|----------|--------|-------------|------|
| 刑事高频 | 8 | 30 | 《刑法》各罪条款映射（第 232~451 条常见罪） |
| 民事高频 | 7 | 40 | 《民法典》合同/侵权/物权编常见案由 |
| 行政高频 | 0 | 15 | 《行政诉讼法》+ 各领域专门法 |
| 其他（知产/执行/国家赔偿） | 0 | 15 | 专属映射 |
