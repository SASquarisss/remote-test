## 1. 产品概述

### 1.1 一句话定义

争点推演沙盘是一个基于法律知识图谱的**对抗式庭审模拟工具**——用户输入案情摘要，系统自动从图谱中激活相关法律概念、法条、要件和判例，生成原告与被告双方的论证路径决策树，帮助用户在庭前"预演"攻防。

### 1.2 核心价值主张

| 现状痛点 | 沙盘解决 |
|----------|----------|
| 庭前准备靠经验+手动查法条，遗漏多 | 图谱自动激活全部相关法律概念，无一遗漏 |
| 只能想到自己的论证，难以预判对方 | 自动生成双方路径，提前看到对方攻击点 |
| 不知道自己的论证哪里最薄弱 | 论证强度指示器量化显示每个节点的可信度 |
| 类案参考需要人工检索比对 | 图谱自动推荐最相关的指导案例和裁判逻辑 |

### 1.3 与本体的关系

沙盘不是独立功能——它是法律本体论知识图谱的**交互式消费端**。图谱是"知识库"，沙盘是"推演引擎"。没有图谱的实体、关系、约束数据，沙盘无法运行。

## 2. 目标用户与场景

### 2.1 用户画像

| 角色 | 典型用户 | 使用频率 | 核心诉求 |
|------|---------|---------|---------|
| **诉讼律师** | 3-8年执业经验，民商诉讼 | 每案庭前1-2次 | 不想遗漏对方可能的抗辩路径，快速识别己方论证弱点 |
| **实习律师** | 1-2年级，正在学习诉讼策略 | 每周3-5次 | 理解一个案件中双方可能的攻防结构，提升策略思维 |
| **企业法务** | 负责诉讼管理，非一线出庭 | 每个案件评估阶段1次 | 在决定外聘律师前快速评估案件的诉讼风险和可能的走向 |
| **法学院师生** | 模拟法庭课程 | 每学期8-10次 | 让学生理解对抗式论证的结构化表达，拆解真实案例 |

### 2.2 使用场景

**场景A：庭前推演（高频）**
周律师下周要开庭，一个买卖合同纠纷案。她把案情摘要录入沙盘，系统生成了双方论证路径。她发现对方可能援引《民法典》第527条（不安抗辩权）作为核心抗辩——这是她之前没考虑到的。她针对该路径准备了反驳证据。

**场景B：案件评估（中频）**
某公司收到起诉状，法务总监需要快速评估应诉风险和预估结果。他把起诉事实输入沙盘，系统展示原告的所有论证路径和强度，并生成被告方可选的反驳路径清单。他据此决定是否和解。

**场景C：模拟法庭训练（低频但深度）**
法学院教授选取一个最高法指导案例，让两组学生分别使用沙盘准备原被告的论证路径。课堂上对比系统生成的最优路径和学生设计的路径，分析差异。

## 4. 功能需求详述

### 4.1 入口与启动

#### 4.1.1 入口位置

在现有知识图谱可视化页面的右侧详情面板（`#detailPanel`）中，已有 Tab 为：📌 基本信息 / 🔗 一跳邻居 / 📄 原始JSON。**在「原始JSON」之后新增第4个 Tab**：

```
[ 📌 基本信息 ] [ 🔗 一跳邻居 ] [ 📄 原始JSON ] [ 🏛️ 推演 ★NEW ]
```

#### 4.1.2 Tab 行为

- 默认状态下，Tab 显示「🏛️ 争点推演沙盘」标题，下方为一个按钮「🔄 开始新推演」
- 如果用户正在推演中（未关闭沙盘），再次点击 Tab 恢复上次的推演状态
- 如果用户从其他模块（如图谱点击）跳转到推演 Tab，保持沙盘状态不变，仅在面板右上角显示小提示「当前推演未中断」

#### 4.1.3 空状态

首次进入或无活跃推演时显示：

```
┌─────────────────────────────────────┐
│  🏛️ 争点推演沙盘                     │
│                                     │
│  输入案情摘要，系统自动生成          │
│  原被告双方的论证路径决策树          │
│                                     │
│  ┌──────────────────────────┐       │
│  │ 输入案情摘要...           │       │
│  └──────────────────────────┘       │
│                                     │
│  可选：选择案由类型                  │
│  [ 民间借贷 ] [ 买卖合同 ] [ ... ]  │
│                                     │
│  [ 🚀 开始推演 ]                    │
│                                     │
│  已分析案件：12 件                  │
└─────────────────────────────────────┘
```

### 4.2 案件输入面板

#### 4.2.1 输入字段

| 字段 | 类型 | 是否必填 | 说明 |
|------|------|---------|------|
| 案情摘要 | 文本域（多行） | 是 | 用户粘贴或输入案件事实描述，建议500字以内 |
| 案由类型 | 下拉单选 | 否 | 从图谱已有 CaseType 列表中选取，辅助提高匹配精度 |
| 核心争议焦点 | 文本域（单行） | 否 | 用户认为本案最关键的争议点，如"借条无出借人签名" |
| 审理程序 | 下拉单选 | 否 | 一审/二审/再审，影响推演的规则适用范围 |

#### 4.2.2 输入校验

- 案情摘要 < 50字符时，按钮禁用并提示"请至少输入50字案情描述"
- 案情摘要 > 2000字符时，弹窗提示"长文本可能降低推演精度，建议精简到500字以内"
- 案由类型与案情明显不符时（如选"侵权"但文本全是合同内容），给出"案由类型与案情描述不匹配？"的建议气泡

### 4.3 图谱激活与推演生成

#### 4.3.1 后台流程（对用户透明）

用户点击「开始推演」后，系统按以下步骤处理：

```
① 案情语义解析
   └─ LLM 从案情中提取关键实体（当事人、法律关系、行为、标的）
   └─ 映射到图谱中的本体类型（如"买卖合同"→ CaseType、LegalSubject）

② 图谱激活
   └─ 在知识图谱中查找被激活实体
   └─ 沿关系边展开 1-2 层邻居，收集相关法条、判例、要件
   └─ 返回激活子图（约 20-50 个节点）

③ 论证路径构建
   └─ 以原告诉求为起点，以 JudgmentResult 为终点
   └─ 使用 A* 搜索 + 逻辑约束在激活子图上搜索可行的论证路径
   └─ 为原告生成支持路径集（正面论证）
   └─ 为被告生成对抗路径集（反驳/抗辩）

④ 强度评估
   └─ 对每个节点统计：
     └─ 在图谱关联案件中出现的频次
     └─ 该节点在支持路径 vs 对抗路径中的占比
   └─ 综合计算论证强度得分（0-100）
```

#### 4.3.2 加载态

推演生成过程中，面板显示加载动画：

```
┌─────────────────────────────────────┐
│  🏛️ 争点推演沙盘                     │
│                                     │
│     🔄 正在分析案情...（1/4）       │
│        正在提取法律实体              │
│                                     │
│  ┌──────────────────────────┐       │
│  │  ■■■■■■■□□□ 45%          │       │
│  └──────────────────────────┘       │
│                                     │
│  预计 8-15 秒                        │
└─────────────────────────────────────┘
```

四个阶段分别显示：
1. 正在分析案情...（提取法律实体）
2. 正在激活知识图谱...（关联法条/判例）
3. 正在构建论证路径...（原告/被告）
4. 正在评估论证强度...（计算评分）

**超时处理**：超过 30 秒未完成，显示「推演生成时间较长，是否继续等待？」按钮和「后台生成，完成后通知我」选项。

#### 4.3.3 空结果处理

如果图谱中找不到与案情相关的实体：

```
┌─────────────────────────────────────┐
│  未能找到与案情相关的法律实体        │
│                                     │
│  可能原因：                         │
│  • 案由类型未在图谱覆盖范围内        │
│  • 案情描述过于笼统                 │
│                                     │
│  [ 返回修改输入 ]  [ 使用通用模型 ]  │
└─────────────────────────────────────┘
```

### 4.4 双向决策树画布

#### 4.4.1 整体布局

推演结果展示在**详情面板的主体区域**，分为上中下三个区域：

```
┌──────────────────────────────────────────────────┐
│  🏛️ 争点推演沙盘               [交换阵营] [导出] │ ← 标题栏
├──────────────────────────────────────────────────┤
│  案情摘要: 原告张三与被告李四...                  │ ← 案情回顾（折叠态，可展开）
├──────────────────────────────────────────────────┤
│                                                  │
│  ┌─── 原告路径 ──────────────────────────┐       │
│  │                                         │       │
│  │  [合同成立] ──→ [效力要件] ──→ [有效]   │       │
│  │    🟢85          🟢78          🟢92    │       │
│  │     ↓                        ↓          │       │
│  │  [签名要件] ──→ [意思表示] ──→ [真实]   │       │
│  │    🔴42          🟡55          🟢81    │       │
│  │                                         │       │
│  └─────────────────────────────────────────┘       │
│                                                    │
│  ┌─── 被告路径 ──────────────────────────┐       │
│  │                                         │       │
│  │  [合同不成立] ← [签名缺失] ← [未意思]  │       │
│  │    🟢73           🟢80          🟢70    │       │
│  │     ↓                        ↓          │       │
│  │  [不安抗辩] ← [履行能力] ← [预期违约]   │       │
│  │    🟡68           🟢75          🟢71    │       │
│  │                                         │       │
│  └─────────────────────────────────────────┘       │
│                                                    │
├──────────────────────────────────────────────────┤
│  📎 关联法条 / 案例                              │ ← 底部详情（点击节点后展示）
│  《民法典》第527条 不安抗辩权                     │
│  指导案例XX号：...                               │
└──────────────────────────────────────────────────┘
```

#### 4.4.2 路径显示规则

- **原告路径**（左侧/上方）：绿色主题色系，箭头方向从左到右（从事实到诉求）
- **被告路径**（右侧/下方）：橙色/红色主题色系，箭头方向从右到左（从诉求到抗辩）
- 两条路径**平行展示**，中间无交叉线，但语义对应的节点（如原告"合同成立" vs 被告"合同不成立"）在纵向上对齐
- 每个节点显示：
  - 实体中文名（如"合同成立"）
  - 论证强度评分（色标圆点 + 数字）
  - 节点类型小图标（📜法条 / ⚖️要件 / 📋判例 / 🔍事实）
- 节点之间的连线显示关系名（如"→ 要件具备 →" / "-- 要件欠缺 →"）

#### 4.4.3 节点最大数量

- 每条路径不超过 10 个节点（超过时折叠为「+N 个次要节点」可展开）
- 总节点数不超过 30 个

### 4.5 论证强度指示

#### 4.5.1 评分体系

每个节点显示一个论证强度评分（0-100），基于以下指标综合计算：

| 指标 | 权重 | 数据来源 |
|------|------|---------|
| 该实体在同类案件中出现频次 | 30% | 图谱中同类案件的实体统计 |
| 该实体关联的法条/判例数量 | 25% | 图谱中该实体的关系边数量 |
| 该实体在胜诉案件中的占比 | 25% | 图谱中 JudgmentResult 关联统计 |
| 该实体与案由类型匹配度 | 20% | 本体论的 CaseType 关联度 |

#### 4.5.2 视觉编码

| 评分范围 | 颜色 | 含义 | 图标 |
|---------|------|------|------|
| 80-100 | 🟢 绿色 | 论证基础扎实 | 实心圆 |
| 50-79 | 🟡 黄色 | 论证中等，需注意 | 半填充圆 |
| 0-49 | 🔴 红色 | 论证薄弱，重点准备 | 空心圆 |

#### 4.5.3 悬停提示

悬停在节点评分上显示工具提示：

```
「合同成立 · 强度 85」
📊 在同类案件中出现率：92%（230/250 件）
📜 关联法律条文：3 条
📋 关联指导案例：5 件
✅ 胜诉关联率：76%
```

### 4.6 节点交互

#### 4.6.1 默认操作

| 操作 | 效果 |
|------|------|
| **单击节点** | 底部详情区显示该节点的完整信息（法条原文、判例摘要、要件分解等） |
| **双击节点** | 在知识图谱主画布中聚焦该实体，高亮显示其 1 跳邻居 |
| **悬停节点** | 显示论证强度工具提示（4.5.3） |
| **拖拽节点** | 改变节点在路径中的位置（仅限同一路径内） |
| **右键节点** | 弹出上下文菜单：查看详情 / 标记为「关键论点」/ 标记为「薄弱点」/ 删除该节点 |

#### 4.6.2 手动编辑

用户可以：
- **添加节点**：在路径任意位置点击「+」按钮，弹出搜索框输入实体名，系统从图谱中查找并插入
- **删除节点**：右键 → 删除，路径自动重连
- **修改连接**：拖拽节点的连线端点到另一个节点，建立新连接（需系统验证语义合理性）
- **添加批注**：在每个节点右下角有一个小图标📝，点击后输入文字批注（仅本地可见）

#### 4.6.3 节点详情面板

单击节点后，底部详情区展示（自上而下）：

```
┌─ 📜 合同成立 ─────────────────────────┐
│                                        │
│  📌 基本定义                           │
│  《民法典》第143条：...                 │
│                                        │
│  ⚖️ 构成要件                          │
│  □ 当事人具有相应民事行为能力          │
│  ☑ 意思表示真实                        │
│  ☑ 不违反法律、行政法规的强制性规定    │
│                                        │
│  📋 关联指导案例                       │
│  • 指导案例XX号：...（点击查看全文）   │
│  • 指导案例XX号：...（点击查看全文）   │
│                                        │
│  📊 同类案件统计                       │

```

### 4.7 交换阵营

#### 4.7.1 功能入口

画布标题栏右侧的「交换阵营」按钮。

#### 4.7.2 行为

点击后，系统执行：

1. 将当前以原告视角标记的路径切换为被告视角
2. 重新计算所有节点的论证强度（同一节点在不同立场下强度可能不同）
3. 路径方向反转（原来原告的论据可能变成被告攻击的靶子）
4. 画布以动画过渡方式翻转（约 500ms 过渡动画）

#### 4.7.3 视觉反馈

过渡期间显示：「🔄 切换至被告视角...」
完成后标题变为：「🏛️ 争点推演沙盘 — 被告视角」
再次点击恢复原告视角。

### 4.8 报告导出

#### 4.8.1 导出格式

| 格式 | 说明 |
|------|------|
| PDF | 排版规范的正式报告，含封面、目录、推演路径图、论证强度评分表 |
| Markdown | 纯文本可编辑版本，供用户二次编辑 |
| JSON | 推演结果的完整结构化数据，可供程序复用 |

#### 4.8.2 报告内容

- 案件基本信息（案情摘要原文、案由类型、输入时间）
- 推演路径概览图（文本化展示双向决策树）
- 每个节点的详细分析（法条引用、判例引用、强度评分及解释）
- 薄弱环节汇总（所有评分 < 50 的节点清单及补强建议）
- 关联法条/判例清单
- 生成时间戳和版本号

## 6. 数据流与状态管理

### 6.1 数据流

```
用户输入案情 → [前端] 发送 POST /api/drill/start
              → [后端] LLM 实体提取 → 图查询激活子图
              → [后端] 路径搜索（A*）+ 强度计算
              → 返回结构化推演结果 JSON
              → [前端] 渲染双向决策树
```

#### API 接口

```
POST /api/drill/start
Request: {
  "summary": "原告张三与被告李四...",
  "case_type": "民间借贷",        // 可选
  "core_dispute": "借条无签名",    // 可选
  "procedure": "first_instance"   // 可选
}

Response: {
  "status": "ok",
  "drill_id": "drill_20260514_001",
  "plaintiff_path": [
    { "id": "entity:contract_formation", "label": "合同成立",
      "type": "legal_element", "score": 85,
      "laws": ["民法典第143条", ...],
      "cases": ["指导案例XX号", ...],
      "strength_detail": { "frequency": 0.92, "win_rate": 0.76, ... }
    },
    ...
  ],
  "defendant_path": [...],
  "activated_graph": { "nodes": [...], "edges": [...] },
  "stats": { "node_count": 12, "path_length": 4, "avg_score": 72 }
}
```

### 6.2 本地状态

| 状态变量 | 说明 | 存储位置 |
|---------|------|---------|
| `drillState` | idle / inputing / loading / ready / error | 前端内存 |
| `currentDrillId` | 当前推演唯一 ID | localStorage |
| `lastInput` | 上次输入内容（用于恢复） | localStorage |
| `activeView` | 原告视角 / 被告视角 | 前端内存 |
| `selectedNode` | 当前选中的节点 ID | 前端内存 |
| `userAnnotations` | 用户添加的节点/批注 | localStorage |

### 6.3 持久化

- 推演结果在 localStorage 中保留 7 天
- 用户可手动「保存推演」到服务端（登录后），存储为个人历史记录
- 推演结果不写入图谱——沙盘是"查询消费"场景，不修改知识图谱数据

## 7. 非功能需求

### 7.1 性能

| 指标 | 目标值 | 测量方式 |
|------|--------|---------|
| 推演生成时间 | ≤ 15 秒（P0）/ ≤ 8 秒（P1 优化后） | 从点击「开始推演」到画布渲染完成 |
| 节点点击响应 | ≤ 200ms | 从点击节点到详情区内容更新 |
| 交换阵营响应 | ≤ 3 秒 | 从点击按钮到新视角完成渲染 |
| 画布滚动流畅度 | 60fps | Chrome DevTools Performance 面板 |
| 并发用户 | ≥ 50 同时推演 | 后端压测 |

### 7.2 可用性

- 全功能支持键盘操作（无障碍）
- 页面文案避免专业黑话（如"拓扑签名""知识图谱激活"不出现于用户界面）
- 每次错误都给出**可操作的建议**而非技术描述（如"案情描述太简短，请补充案件事实"而非 "Error: 422"）

### 7.3 兼容性

- 支持 Chrome 90+、Edge 90+、Firefox 90+
- 不支持 IE
- 移动端浏览器暂不优化（面板宽度 400px 在小屏幕上显示不全）

## 10. 附录：术语表

| 术语 | 英文 | 解释 |
|------|------|------|
| 论证路径 | Argument Path | 从案件事实到裁判结论的一系列推理步骤，每一步由图谱实体表示 |
| 论证强度 | Argument Strength | 定量指标（0-100），表示一个论证节点的可信度和法律支持力度 |
| 激活子图 | Activated Subgraph | 从知识图谱中根据案情动态提取的相关实体和关系的子集 |
| 双向决策树 | Dual Decision Tree | 同时展示原告和被告两条论证路径的可视化结构 |
| 交换阵营 | Switch Side | 一键从原告视角切换到被告视角（或反之），重新审视论证路径 |
| 推演 ID | Drill ID | 每次推演的唯一标识符，用于后续检索和报告引用 |
