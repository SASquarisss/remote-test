## 详细发现

### 1. cron_pre_run.py 存在硬编码绝对路径
- **位置**：`scripts/cron_pre_run.py` 第13行
- **严重程度**：🔴 严重
- **描述**：`REPO = Path("/root/.hermes/hermes-agent/remote-test")` 是写死的绝对路径，在其他机器或Docker环境中直接无法运行。与 `review_state.py` 的硬编码路径问题相同，破坏了代码的可移植性。
- **建议修复**：
  ```python
  REPO = Path(__file__).resolve().parent.parent
  ```

### 2. cron_pre_run.py 硬编码 .env 文件路径
- **位置**：`scripts/cron_pre_run.py` 第18行
- **严重程度**：🟡 警告
- **描述**：硬编码 `/root/.hermes/.env` 路径，在其他环境中无法运行。应通过环境变量或相对路径获取配置。
- **建议修复**：
  ```python
  ENV_PATH = os.getenv("HERMES_ENV", Path.home() / ".hermes" / ".env")
  ```

### 3. auto_iterative_test.py 裸 except 捕获所有异常
- **位置**：`scripts/auto_iterative_test.py` 第375-376行
- **严重程度**：🔴 严重
- **描述**：`get_untested_ids()` 中读取 jsonl 时使用裸 `except:` 捕获所有异常，这会静默吞掉 `KeyboardInterrupt`、`SystemExit` 等不应被捕获的异常，且隐藏真正的错误信息，导致调试困难。
- **建议修复**：
  ```python
  except (json.JSONDecodeError, ValueError) as exc:
      pass
  ```

### 4. auto_iterative_test.py 硬编码CSV文件名
- **位置**：`scripts/auto_iterative_test.py` 第31行
- **严重程度**：🟡 警告
- **描述**：`MASTER_CSV` 指向一个带特定时间戳的CSV文件名（`DataWorks_Excel_207022225952236023_20260427150349.csv`）。当数据源更新或文件名变化时，脚本会直接失效。
- **建议修复**：使用 `glob` 匹配 `data/raw/*.csv` 或从配置文件/命令行参数传入路径。

### 5. auto_iterative_test.py 缺少异常重试机制
- **位置**：`scripts/auto_iterative_test.py` 第455行
- **严重程度**：🟡 警告
- **描述**：`run_llm_extraction` 对每个 case 顺序调用LLM，只有 `time.sleep(1)` 防限流，没有重试机制。若API临时故障或限流，整个批次会失败。虽然已有 `time.sleep(1)`，但缺乏指数退避和失败记录。
- **建议修复**：引入 `retry_on_error` 装饰器（与 `daily_review.py` 保持一致），增加失败case的ID记录以便下次优先重试。

### 6. try_auto_fix 函数名与行为不符
- **位置**：`scripts/auto_iterative_test.py` 第548行
- **严重程度**：🟢 建议
- **描述**：`try_auto_fix` 函数声称"尝试自动修复低风险问题"，但实际仅返回字符串描述（如"案号提取率低，已记录需增加变体示例"），并未真正修改 prompt 文件或代码。函数名与行为不符，存在误导。
- **建议修复**：将函数名改为 `record_issues_for_manual_fix` 或真正实现prompt的自动追加修改。

### 7. daily_review.py 冲突标记检测修复正确但缺少注释
- **位置**：`scripts/daily_review.py` 第764行
- **严重程度**：🟢 建议
- **描述**：将 `any(marker in text)` 改为 `re.search(r'^(<{7}|={7}|>{7})', text, re.MULTILINE)` 是正确的修复方向，但当前正则使用 `^{7}` 语法在Python中会被解析为字面量 `{7}`（有效的re重复语法），功能正确。建议增加注释说明此正则不匹配Markdown引用块中的 `>>>>>>>` 等场景。
- **建议修复**：在正则上方增加注释 `# 仅匹配行首的 git 冲突标记（<<<<<<< / ======= / >>>>>>>），避免误判正文中的 markdown 引用符号`。

### 8. status.json 存在 9 条 failed_patch 记录

  3. 考虑在patch失败时降级为创建issue而非静默失败

### 9. auto_iterative_test.py 缺少 JSON Schema 验证
