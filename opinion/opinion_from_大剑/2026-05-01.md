### 3. cron_pre_run.py 缺少子进程错误处理
- **位置**：`scripts/cron_pre_run.py` 第31-37行
- **严重程度**：🟡 警告
- **描述**：`subprocess.run` 执行 `auto_iterative_test.py` 后未检查 `returncode`。若测试脚本失败（非零退出码），当前脚本仍会继续执行并输出可能误导的状态信息。
- **建议修复**：
```python
result = subprocess.run(...)
if result.returncode != 0:
    print(f"ERROR: auto_iterative_test.py exited with code {result.returncode}")
    print(result.stderr)
    sys.exit(result.returncode)
```

### 4. auto_iterative_test.py 裸 except 捕获所有异常
- **位置**：`scripts/auto_iterative_test.py` 第65行
- **严重程度**：🔴 严重
- **描述**：使用裸 `except:` 捕获所有异常（包括 `KeyboardInterrupt`、`SystemExit`），会隐藏真正的错误并导致调试困难。该问题在读取历史测试记录时触发，若 JSON 格式损坏，错误被静默吞掉。
- **建议修复**：
```python
try:
    obj = json.loads(line)
    rid = obj.get('id') or obj.get('case_id')
    if rid:
        tested.add(str(rid))
except (json.JSONDecodeError, KeyError, TypeError):

```

### 6. auto_iterative_test.py 缺少异常重试机制
- **位置**：`scripts/auto_iterative_test.py` 第112-120行（API调用处）
- **严重程度**：🟡 警告
- **描述**：LLM API 调用仅有一次尝试，网络波动或 API 限流会导致整批数据丢失。虽已添加 `timeout=60`，但仍无重试机制。对于批量处理数百条数据的场景，单点失败代价过高。
- **建议修复**：添加指数退避重试：
```python
for attempt in range(3):
    try:
        response = client.chat.completions.create(...)
        break
    except Exception as e:
        if attempt == 2:
            raise
        time.sleep(2 ** attempt)
```
