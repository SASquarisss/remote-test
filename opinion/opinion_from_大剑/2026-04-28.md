## 详细分析

### 1. 本体论结构评估

#### 优势亮点
✅ **三层架构设计优秀**
- 规范层（LegalNorm）：涵盖法律、法条、指导性案例、量刑标准等完整法律规范体系
- 主体层（LegalSubject）：清晰区分自然人/法人，支持跨案件消歧策略
- 案件层（JudicialEntity）：完整覆盖案件全生命周期，从立案到执行

✅ **关系模型完备**
- `cites`：案件引用法条（含位置、目的属性）
- `guides_case_type`：指导性案例指导案由适用
- `plays_role`：主体在案件中担任角色（动态属性）
- `represents`：律师代理关系（含授权范围、期限）

✅ **约束机制健全**
- 案号正则校验：`(YYYY)XX法院民初第N号`
- 统一社会信用代码：18位标准校验
- 时序约束：`filing_date < judgment_date < effective_date`
- 脱敏规则：符合个保法要求

#### 改进建议
⚠️ **实体类型枚举值优化**
- 当前 `LegalSubject.subject_type` 使用 `natural_person`/`organization`
- 建议增加 `government_agency` 枚举值以提高语义精确度
- 影响范围：解析脚本中的主体分类逻辑

## 具体问题列表

### 高优先级问题
1. **主体类型枚举不匹配** 
   - 位置：`ontology/schemas/legal_ontology_v2.yaml` 第69行
   - 问题：`Person.type_enum` 包含 `legal_person`，但实际使用中法人应归入 `Organization`
   - 建议：移除 `legal_person`，统一使用 `Organization` 表示法人实体

2. **角色编码表缺失**
   - 位置：`extraction/llm_extractors/prompt_v2.txt` 第16-30行
   - 问题：缺少 `appellant`/`appellee`/`retrial_applicant` 等上诉相关角色
   - 建议：补充完整的诉讼程序角色编码

### 中优先级问题
3. **配置文件安全性**
   - 位置：`config.yaml` 第14、20、33行
   - 问题：密码明文存储
   - 建议：集成密钥管理服务或环境变量引用

4. **批量处理性能**
   - 位置：`extraction/llm_extractors/guiding_case_extractor.py` 第275-352行
   - 问题：单线程处理，大规模数据效率较低
   - 建议：增加并行处理支持

## 可落地的修复方案

### 方案一：本体论结构调整（推荐优先实施）
```yaml
# 修改 ontology/schemas/legal_ontology_v2.yaml
Person:
  is_a: LegalSubject
  required: [name, type]
  optional: [gender, birth_date, nationality, desensitized_id_number, address, phone]
  type_enum: [natural_person]  # 移除 legal_person
  description: "自然人（跨案件不消歧，每个案件独立节点）"

Organization:
  is_a: LegalSubject  
  required: [org_type, credit_code]
  optional: [legal_representative, registered_capital, business_scope, legal_name_alias]
  org_type_enum: [company, government_agency, ngo, law_firm, expert_institution, court, procuratorate, legal_person]
  description: "组织机构（企业用credit_code跨案件全局关联，包含法人实体）"
```
