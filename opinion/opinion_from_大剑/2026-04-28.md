## 具体问题分析

### 🔴 高优先级问题

#### 1. **安全凭证硬编码风险**
**位置**: `config.yaml` (第14行, 第20行, 第33行)
**问题**: 数据库密码、MinIO密钥等敏感信息直接硬编码在配置文件中
```yaml
# config.yaml lines 13-14
user: "neo4j"
password: "legalkg2026"

# config.yaml lines 19-20  
user: "root"
password: "legalkg2026"

# config.yaml lines 32-33
access_key: "legalkg"
secret_key: "legalkg2026"
```
**影响**: 安全风险，生产环境不应包含明文凭证
**建议**: 
- 使用环境变量引用 `${NEO4J_PASSWORD}` 等
- 或使用Vault等密钥管理服务
- 至少添加到.gitignore并提供示例配置文件

#### 2. **API密钥处理不当**
**位置**: `webui/backend/parser_bridge.py` (第29-33行)
**问题**: 直接从环境变量读取OPENAI_API_KEY，但错误处理不够友好
```python
api_key = os.environ.get("OPENAI_API_KEY")
if not api_key:
    raise RuntimeError("缺少 OPENAI_API_KEY 环境变量")
```
**影响**: 运行时错误，用户体验差
**建议**: 
- 添加更友好的错误处理和配置引导
- 提供配置文件或.env支持
- 考虑使用配置类统一管理

### 🟡 中优先级问题

#### 3. **输入验证不足**
**位置**: `api/routers/query.py` 多个接口
**问题**: 缺少对输入参数的完整验证，特别是日期格式、金额范围等
- `filing_date_after` 字段缺少日期格式验证
- `claim_amount` 字段缺少非负数验证
- `disputed_issues` 分割逻辑可能出错（第88行）

**影响**: 可能导致后端异常或错误结果
**建议**: 
- 添加Pydantic自定义验证器
- 对日期字段添加格式验证
- 对金额字段添加范围限制

#### 4. **错误处理过于宽泛**
**位置**: `api/routers/query.py` (第65行, 第76行, 第100行, 第122行)
**问题**: 使用通用Exception捕获，返回500错误，缺乏具体错误信息
```python
except Exception as e:
    raise HTTPException(status_code=500, detail=str(e))
```
**影响**: 调试困难，用户体验差
**建议**: 
- 区分不同类型的异常（数据库连接错误、查询语法错误等）
- 返回具体的错误码和消息
- 记录详细的错误日志

#### 5. **缺少分页支持**
**位置**: `api/routers/query.py` 组织机构查询接口 (第104-123行)
**问题**: limit参数有上限但缺少offset分页支持
**影响**: 大数据量时无法完整获取结果
**建议**: 
- 添加offset参数支持分页
- 或使用游标分页机制
