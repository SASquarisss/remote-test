### 3. `generate_ontology_viz.py` 缺少错误处理和日志
- **位置**：`scripts/generate_ontology_viz.py:338-345`
- **严重程度**：🟡 警告
- **描述**：`main()` 函数直接调用 `load_yaml()` 和 `build_graph()`，没有处理 YAML 文件不存在、格式错误、或 JSON 序列化异常的情况。如果 YAML 文件中有循环引用或特殊字符，HTML 模板替换可能产生无效 JavaScript。
- **建议修复**：
```python
def main():
    try:
        yaml_en = load_yaml(YAML_EN)
        yaml_zh = load_yaml(YAML_ZH)
    except FileNotFoundError as e:
        print(f"❌ YAML文件缺失: {e}")
        return 1
    except yaml.YAMLError as e:
        print(f"❌ YAML解析错误: {e}")
        return 1
    
    try:
        node_list, edge_list = build_graph(yaml_en, yaml_zh)
        html = HTML_TEMPLATE.replace("__NODES__", json.dumps(node_list, ensure_ascii=False))
        html = html.replace("__EDGES__", json.dumps(edge_list, ensure_ascii=False))
        with open(OUT_HTML, "w", encoding="utf-8") as f:
            f.write(html)
        print(f"✅ 已生成: {OUT_HTML}")
        return 0
    except Exception as e:
        print(f"❌ 生成失败: {e}")
        return 1

if __name__ == "__main__":
    exit(main())
```
注意：HTML_TEMPLATE 中的占位符 `{nodes}` 和 `{edges}` 需要改为不与 Python str.format() 冲突的格式（如 `__NODES__` / `__EDGES__`），因为 `{` 在 str.replace 中虽安全，但后续若改用 format 会出错。

### 4. `extract_legal_provisions_regex.py` 模式B statute 清洗逻辑存在潜在误伤
- **位置**：`scripts/extract_legal_provisions_regex.py:153-163`
- **严重程度**：🟡 警告
- **描述**：新增的 statute 清洗逻辑 `re.sub(r'^[^\w\u4e00-\u9fa5]+', '', statute)` 使用 `\w`（等价于 `[a-zA-Z0-9_]`）和中文字符。但 statute 名称可能包含合法标点（如"《刑法》"中的书名号已在前面去除，但"（刑法）"中的括号会被清洗）。更严重的是，如果 statute 以数字开头（如"2021年修订的刑法"），数字会被保留，但"年修订的"这部分可能被意外截断。
- **建议修复**：
```python
# 更精确的清洗：仅去除常见前缀标点，保留中文、英文、数字
def clean_statute(statute: str) -> str:
    # 去除开头标点、空白、连接词
    statute = re.sub(r'^[\s\u3000,.;:!?，。；：！？、""''（）【】《》]+', '', statute)
    # 去除常见前缀词
    for prefix in ['的', '之', '和', '与', '及']:
        if statute.startswith(prefix):
            statute = statute[len(prefix):]
    return statute.strip()
```
